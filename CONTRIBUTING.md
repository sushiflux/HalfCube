# Contributing to HalfCube · Mitwirken an HalfCube

**[English](#english) · [Deutsch](#deutsch)**

> As of 2026-11-27 / Stand 27.11.2026.

## English

### Current state

HalfCube does **not accept code contributions** (pull requests) at the moment. The foundation still changes every day, so outside code would often be outdated before anyone could look at it. Only the developer can open pull requests in this repository.

**Issues are welcome.** You can use them for bug reports and for ideas.

### Reporting a bug

Open an [issue](https://github.com/sushiflux/HalfCube/issues) and include:

1. **What you did**, step by step, so that someone else can repeat it.
2. **What you expected** and **what happened instead.**
3. **The version.** Open "About HalfCube" (the "i" in the title bar) and copy the version with "Copy version".
4. **The Windows version** and the version of Windows you use.
5. **The full error message**, if the program showed one. Each message has a button to copy it. Paste it as it is, with its code (for example `HC-FILE-003`).
6. **A screenshot** or a small example file, if that helps. Do not send files with private or confidential content.

One problem per issue makes it easier to follow.

### Suggesting an idea

Open an [issue](https://github.com/sushiflux/HalfCube/issues) and describe:

1. **What you want to do** (your goal, not only the feature you imagine).
2. **How you do it today** and what is hard about it.
3. **Examples**, such as a part you want to build.

Ideas are collected and sorted into the plan. An issue is not a promise that the idea is built.

### How it will open later

When HalfCube is stable, contributions will open step by step, starting with **translations and small fixes**. Then pull requests will need a pull request template and a green automatic check (CI). The rules will be written here before that happens. Until then, please do not send pull requests.

### Rights to contributions: a CLA

Before code from others is accepted, every contributor signs a short **Contributor License Agreement (CLA)** once. It gives the project the right to use the contribution and to pass it on under another license later. The contributor **keeps the copyright**.

Why: HalfCube's code is under the PolyForm Shield License, and the developer may move to a more open license later. With a CLA the developer can do that alone. Without one, it would need the agreement of every contributor whose code is in the program.

The text of the agreement will be published here when contributions open. Until then, no code contributions are accepted.

## Deutsch

### Heutiger Stand

HalfCube nimmt derzeit **keine Code-Beiträge** (Pull Requests) an. Das Grundgerüst ändert sich noch täglich, fremder Code wäre oft schon veraltet, bevor jemand ihn ansehen könnte. Nur der Entwickler kann in diesem Repository Pull Requests eröffnen.

**Issues sind willkommen.** Du kannst sie für Fehlermeldungen und für Ideen nutzen.

### Einen Fehler melden

Eröffne ein [Issue](https://github.com/sushiflux/HalfCube/issues) und schreibe dazu:

1. **Was du getan hast**, Schritt für Schritt, damit jemand anderes es wiederholen kann.
2. **Was du erwartet hast** und **was stattdessen passiert ist.**
3. **Die Version.** Öffne „Über HalfCube“ (das „i“ in der Titelleiste) und kopiere die Version mit „Version kopieren“.
4. **Die Windows-Version** und die Version von Windows, die du benutzt.
5. **Die vollständige Fehlermeldung**, wenn das Programm eine gezeigt hat. Jede Meldung hat einen Knopf zum Kopieren. Füge sie unverändert ein, mit ihrem Code (zum Beispiel `HC-FILE-003`).
6. **Einen Screenshot** oder eine kleine Beispieldatei, wenn das hilft. Schicke keine Dateien mit privaten oder vertraulichen Inhalten.

Ein Problem pro Issue macht es leichter, den Überblick zu behalten.

### Eine Idee vorschlagen

Eröffne ein [Issue](https://github.com/sushiflux/HalfCube/issues) und beschreibe:

1. **Was du erreichen willst** (dein Ziel, nicht nur die Funktion, die du dir vorstellst).
2. **Wie du es heute machst** und was daran schwierig ist.
3. **Beispiele**, etwa ein Teil, das du bauen möchtest.

Ideen werden gesammelt und in den Plan einsortiert. Ein Issue ist kein Versprechen, dass die Idee gebaut wird.

### Wie es später aufgeht

Wenn HalfCube stabil ist, öffnen sich Beiträge schrittweise, zuerst für **Übersetzungen und kleine Korrekturen**. Dann brauchen Pull Requests eine Pull-Request-Vorlage und eine grüne automatische Prüfung (CI). Die Regeln stehen vorher hier. Bis dahin schicke bitte keine Pull Requests.

### Rechte an Beiträgen: eine CLA

Bevor Code von anderen angenommen wird, unterschreibt jeder Beitragende einmal eine kurze **Beitragsvereinbarung (CLA, Contributor License Agreement)**. Sie gibt dem Projekt das Recht, den Beitrag zu nutzen und ihn später auch unter einer anderen Lizenz weiterzugeben. Der Beitragende **behält das Urheberrecht**.

Warum: Der Code von HalfCube steht unter der PolyForm Shield License, und der Entwickler wechselt vielleicht später zu einer offeneren Lizenz. Mit einer CLA kann er das allein tun. Ohne sie bräuchte er die Zustimmung jedes Beitragenden, dessen Code im Programm steckt.

Der Text der Vereinbarung erscheint hier, wenn Beiträge geöffnet werden. Bis dahin werden keine Code-Beiträge angenommen.
