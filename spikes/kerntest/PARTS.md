# Kernel test: fixed test parts

Both candidate kernels (OCCT and USD BRep/SMLib) build exactly these parts. All values are in millimetres, Z points up,
angles in degrees unless stated. A test passes when the kernel produces a result that its own validity checker accepts,
in reasonable time. A clean failure with an error message is recorded as such; an invalid result reported as success is
the worst outcome and must be flagged.

## P1 – Fillet at the edge of a hole

Base block for P1a, P1b, P1d: box from (0, 0, 0) to (80, 50, 20).

| Case | Construction | Operation |
|---|---|---|
| P1a | Through hole Ø20, axis parallel to Z through (40, 25), cut through the full height | Constant fillet r = 3 on the circular edge where the hole meets the top face (z = 20) |
| P1b | Same as P1a | Variable fillet on the same edge, radius 2 at the point (50, 25, 20) rising linearly to 5 halfway round the edge and back to 2 (record whether the kernel supports variable radii at all) |
| P1c | Box from (0, 0, 0) to (40, 40, 40) | Constant fillet r = 5 on all 12 edges (three fillets meet in every corner) |
| P1d | Through hole Ø20, axis parallel to Z through (14, 25), so the wall to the face x = 0 is 4 thick | Fillet the top hole edge with r = 3 (should work), then separately with r = 5 (the fillet would break through the side face; record whether the kernel fails cleanly or returns something invalid) |

## P2 – Shell (hollow out)

| Case | Construction | Operation |
|---|---|---|
| P2a | Box from (0, 0, 0) to (60, 40, 30) | Remove the top face (z = 30), wall thickness 2 inward |
| P2b | Box from (0, 0, 0) to (50, 50, 30), its four top edges filleted r = 5 | Remove the top face, wall thickness 2 inward (if the kernel has an option for extended offsets, run both settings) |
| P2c | Box from (0, 0, 0) to (60, 40, 30) with a vertical through hole Ø10 through (30, 20) | Remove the top face, wall thickness 2 inward (the hole wall must become a tube) |

## P3 – Loft (solid through cross-sections)

| Case | Sections | Operation |
|---|---|---|
| P3a | Circle Ø40 centred on the Z axis at z = 0; square 30 × 30 centred on the Z axis at z = 40 (edges parallel to X and Y); circle Ø20 centred on the Z axis at z = 80 | Smooth (not ruled) solid loft through all three |
| P3b | Rectangle 40 (X) × 20 (Y) centred on the Z axis at z = 0; circle Ø30 centred on the Z axis at z = 50 | Smooth solid loft |

Record whether the kernel needs a manual vertex mapping between sections with different vertex counts.

## P4 – Sweep (profile along a path)

| Case | Profile | Path | Operation |
|---|---|---|---|
| P4a | Circle Ø8 in the plane x = 0, centred on the origin | Line (0, 0, 0) → (50, 0, 0), tangent arc r = 20 turning 90° towards +Y ending at (70, 20, 0), line → (70, 60, 0) | Solid pipe |
| P4b | Circle Ø4 perpendicular to the path at its start | Helix around the Z axis, radius 15, pitch 10, 5 turns, starting at (15, 0, 0) | Solid spring; record the orientation mode used (Frenet, fixed or similar) |

## P5 – STEP round trip

| Case | Input | Operation |
|---|---|---|
| P5a | Every successful result of P1 to P4 | Write to STEP (record AP214 or AP242), read back, compare volume (relative difference), face count and validity |
| P5b | STEP files exported from another CAD program by the project owner, if present in the local test-file folder | Read, check validity, volume and face count; cut a Ø5 cylinder along Z through the centre of the bounding box over its full height; write the result to STEP so the owner can reopen it in the original program |

## P6 – WebAssembly

Build the kernel (only the modules P1 to P4 need, plus STEP if the kernel has it) with Emscripten. Run at least P1a and
P3a under Node.js. Record: size of the `.wasm` file raw, gzip and brotli; size of the JavaScript glue; time to
instantiate; peak linear memory; run time of P1a compared with the native build.

## Extra criteria

| Id | What | How |
|---|---|---|
| E1 | Naming and history | For P1a and for the hole cut of P1a: does the API report per face which faces were modified, generated or deleted? Show the actual map for P1a (original faces → result faces, faces generated by the fillet). |
| E2 | Triangle meshes | Tessellate the results of P1a, P3a and P4b with a chordal tolerance of 0.05 and an angular tolerance of 20°. Record triangle count, time and whether the mesh is watertight (no cracks along shared edges). |
| E3 | Building | Windows (MSVC) and Linux (GCC), both C++20, release builds: clean build time, notable warnings, size of the libraries the tests need. |
| E4 | STEP without its own support | If a kernel has no STEP of its own: which parts of OCCT would provide it, and how much size that adds. |
| E5 | API | Quality of error reporting (codes, messages), documented thread safety, statements on API stability. |

## Measurement rules

- Release builds only. Times are wall-clock medians of 5 runs after one warm-up run.
- Validity with each kernel's own checker; volume, surface area, face and edge count and bounding box from the kernel itself.
- Numbers with four significant digits, units mm, mm², mm³.
- Record exact library versions, compiler versions and compiler flags.
